# Codex memo O: review of step1_plan.md (Phase 3)

Codex (high effort), 2026-09-24, reviewing the Step 1 plan draft against the current code. Input, not decisions.

1. **Queued spawns bypass the Send limit.** The plan keeps the limit unchanged while delaying `add_child` ([plan:115](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/planning/phase3/step1_plan.md:115)), but `WaveManager.can_send_wave()` counts only layer children ([wave_manager.gd:87](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/scripts/wave_manager.gd:87)). Several sends before the next tick therefore see the same count. **Change:** count active admitted enemies plus pending spawns, updating synchronously when queued. Preserve the existing rule: sending at exactly 30 is allowed; automatic waves remain unrestricted. Test repeated sends without advancing physics, the 30/31 boundary, and removed-but-not-yet-freed enemies.

2. **`collect()` loses the current check between successive hits.** Today Wolf checks enemy state before every emission ([mount_wolf.gd:54](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/scripts/mount_wolf.gd:54)). Returning repeated enemy references for a long tick means all entries are collected before the first lethal hit happens. Checking activity only inside `collect()` cannot prevent later emissions, sounds, or future statuses. **Change:** recheck validity/activity before every returned entry is emitted or applied; explicitly pass `mount` into `take_damage(amount, mount)`. Test a first-pass kill during a multi-turn tick, plus two mounts targeting the same enemy: one death, reward, kill credit, and killer.

3. **The pending queue needs an ownership and admission contract.** Detached Nodes will not be freed automatically with Game’s children. Iterating the live pending array also risks admitting spawns appended by admission callbacks. **Change:** at tick entry, swap the queue into a local batch; new requests always enter the next batch. Game owns and frees unadmitted nodes on exit/reset. Configure tier and reward when the spawn is requested, not when admitted. State the complete order: admit batch → GameState → enemy movement → snapshot → carousel. Test spawning during admission and during combat, quitting with pending nodes, and switching tier before admission.

4. **Removal must become effective before cleanup emits signals.** “Before `queue_free()`” ([plan:105](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/planning/phase3/step1_plan.md:105)) is insufficient: `_remove_enemy()` currently calls `unregister_latch()` first, which emits synchronous signals ([game.gd:253](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/scripts/game.gd:253)). A listener could still interact with that enemy during cleanup. **Change:** mark removed as the first operation, make cleanup idempotent, and preserve DEAD-before-`died.emit`. Keep validity checks for stored Node references; `is_active()` cannot safely be called on an already freed object. Add a reentrant cleanup test.

5. **Make initialization and reward migration explicit.** `configure()` runs before `add_child`, but `_ready()` currently resets health from base data ([enemy_base.gd:43](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/scripts/enemy_base.gd:43)). The plan’s general accessor list covers the readers conceptually, but should explicitly name initial health, health-bar fraction/offset, and `setup()`’s stop distance—not just movement and payout. **Change:** `_ready()` initializes Grey only if unconfigured, then initializes health from effective maximum. WaveManager configures once; Game pays exactly `get_kill_gold()`. Remove both the old `gold_multiplier` assignment and payout multiplication. Test a configured Green early-send enemy through admission, damage, latching, and death; its reward is base × 1.45 × 1.5.

6. **Bearing initialization and rebasing need precise timing.** Updating bearings inside base `advance()` can precede a subclass’s sideways movement; `EnemyLeaf.advance()` already demonstrates subclasses doing work after `super` ([enemy_leaf.gd:9](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/scripts/enemy_leaf.gd:9)). Placement rebasing can also inspect a stale snapshot between physics ticks. **Change:** initialize the bearing from the actual spawn position and center, then update it after the complete movement override, before snapshot consumption. Explicitly call `rebase()` after placement using current geometry, retaining existing pass memory. Test both seam directions, zigzag exit/re-entry, radial exit/re-entry, and buying/selling mounts between ticks.

7. **Specify the exact finite-segment formula rather than the center-based description.** The wording at [plan:84](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/planning/phase3/step1_plan.md:84) misses cases where the center lies inside the segment but the tangent point lies inside its inner endpoint. Conversely, a center just beyond the outer endpoint can still use the full tangent window. **Change:** copy memo L’s formula: after radial rejection, for `d > r`, use `q = clamp(sqrt(d²−r²), inner, outer)` and the clamped cosine-law angle. Define center-containing/degenerate cases explicitly. Test both endpoints, exact tangency, and transitions into the ordinary `asin` window. Leave Elephant geometry undecided.

8. **Wave validation needs a stronger fallback invariant.** An uncapped entry alone does not guarantee filling: it could be locked or have zero weight ([plan:186](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/planning/phase3/step1_plan.md:186)). **Change:** require an always-unlocked, positive-weight, uncapped valid entry; reject negative/nonfinite weights and invalid counts/intervals. Exclude zero-weight entries outright, renormalize eligible weights each draw, and apply caps across the whole wave before splitting into clusters. Add deterministic boundary tests alongside seeded sampling. The starting multipliers look consistent, but weights are not final percentages after caps. Green’s Rock appears in only about 20.5% of unlocked waves, so its introduction may take several waves after kill 40; document that expectation.

9. **The generic interface needs one small extension point for effects.** Step 2 removes type branches, but “Step 4 adds statuses here” in Game ([plan:66](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/planning/phase3/step1_plan.md:66)) invites those branches back. **Change:** specify a mount-owned sweep-effect hook that Game dispatches to, with ordinary damage as the default. Sloth can later override it without a central type switch. Keep `MountSweep` responsible only for contact/pass detection; defer a general ability framework, Panda turn payments, and multi-latch targeting until their decisions exist.

10. **Preserve integration coverage when adapting existing tests.** Current helpers assume immediate admission ([test_combat.gd:60](C:/Users/Garret/Dev/Godot/IdleCarousel/idle-carousel/tests/test_combat.gd:60)); Wolf tests turn the carousel without rebuilding a snapshot. Moving everything to helper tests could hide broken Game wiring. **Change:** update fixtures to advance the real admission/snapshot path, retain real Wolf/Horse integration tests, and add a long-range approaching-target case. Add a rendered check for sprite squash recovery, tint survival, and smooth tumble; scene loading alone cannot verify these.

- Separate tint, flash, and health-bar branches. Sprite interpolation OFF preserves inherited parent smoothing, as the [Godot 4.7 documentation confirms](https://docs.godotengine.org/en/4.7/tutorials/physics/interpolation/advanced_physics_interpolation.html).
- Deferring unresolved boss and mount decisions, with same-GPU performance measurements.
